# 互动声音叙事渲染器

一个纯前端的实时空间音频叙事渲染器：一段固定的环境**声床**与三个独立**声音对象**
（鸟鸣 / 脚步 / 钟声）共同组成场景。每个对象带有位置、声源范围、增益、优先级和随
时间变化的轨迹，运行时按统一时间基准真实计算左右声道，而不是把对象压成中心单声道
后只更新画面。

## 如何启动（界面入口）

浏览器要求 AudioContext 必须由用户手势启动，因此：

1. 打开页面后，首先看到“启动对象声音”遮罩。
2. 点击 **启动对象声音** 按钮，音频内核才会创建 AudioContext、加载 AudioWorklet 并构建信号链。
3. 建议佩戴立体声耳机；随后用 **播放 / 暂停 / 时间轴 / 跳转** 控制，用 **段落 A / B** 切换叙事。

推荐用本地静态服务器运行（AudioWorklet 在 `file://` 下可能受限，会自动降级）：

```bash
python3 -m http.server 8000
# 浏览器访问 http://localhost:8000/
```

也可直接用浏览器打开 `index.html`；若 Worklet 无法加载，系统会显式降级到主线程双增益
声像，并在“对象声音反馈”区上报，不会静默失败。

## 文件结构与信号链

```
index.html                  页面骨架（启动遮罩 + 视窗 + 控件 + 结果区）
css/styles.css
js/
  spatial-worklet.js        AudioWorklet 处理器（采样级空间化，独立无 import）
  spatial-math.js           与 worklet 完全一致的空间数学（降级路径与测试共用）
  sound-sources.js          全部声源的程序化 AudioBuffer 合成（无外部音频文件）
  narrative.js              3 个对象、2 个叙事段落、轨迹函数与事件表
  kernel.js                 对象声音内核 AudioKernel：图、时钟、预算、降级、导出
  view.js                   空间音画视窗（canvas 轨迹 / 范围 / 拖拽）
  wav-encode.js             离线渲染结果 -> 16-bit PCM WAV
  main.js                   控件绑定（由内核驱动）
tests/logic.test.mjs        Node 纯逻辑测试（空间数学 / 路径 / 事件 / WAV 头）
```

实时信号链：

```
对象 buffer source(单声道, 循环, 按统一时钟取模对齐)
  -> 对象增益(基础增益 × 事件 accent × 独听衰减)
  -> 空间声道(AudioWorklet：等功率声像 + 距离 + 范围 crossfeed + 折叠)
  -> master -> 安全限制器(DynamicsCompressor) -> 扬声器/耳机
环境声床 buffer source(立体声, 循环) -> 低通滤波 -> 声床增益 -> master
```

## 明确声明的空间化方法

听者固定在原点 `(0,0)`、面向 `+Y`；`X` 负为左、正为右，单位为米，场域半径 10 m。
对每个对象在每个采样（worklet）或每个 tick（降级）计算：

1. **距离增益**：`distGain = FAR / (FAR + max(dist, NEAR))`，`NEAR=0.6`、`FAR=14`。
2. **等功率声像**：`pan = x / dist`，`theta=(pan+1)·π/4`，`gL=cos θ`、`gR=sin θ`，
   保证 `gL²+gR²` 恒定（能量守恒），而非简单线性平衡。
3. **声源范围（crossfeed）**：`width = clamp(1 − dist/range, 0, 1)`。听者在范围外时
   是点声源；进入范围后向等幅双单声道交叉混合，距离越近越像“包围”听者，而不是到了
   某个阈值突然静音或跳到正中。
4. **折叠系数 fold**：资源降级时在等功率声像与中心等功率双单声道之间插值，始终保持有声。

## 混合约定（避免重复计入）

- 声床是**固定立体声床**，只走“床滤波 → 床增益 → master”，**永不进入**任何空间声道。
- 每个对象是**单声道**，只经过自己的一个空间声道；不存在同一对象既进空间声道又直连 master 的路径。
- 两条支路只在 `master` 相加一次，随后经过同一个安全限制器。
- “独听”不是删除其他声源，而是把非独听支路衰减到 8%（声床或对象各自规则一致），便于 A/B 检查。

## 统一时间基准与“旧位置声音”问题

- 所有 source 都是循环 buffer，播放偏移由 `timelinePos % bufferDuration` 决定，音频内容与
  时间严格对齐。
- **暂停**会销毁全部 buffer source 节点；恢复时按当前时间重建，因此不会有停在旧位置的尾音。
- **跳转 / 切段落**会先停 source、清空已触发事件与手动锚点、（跨段时）重建该段 buffer，
  再按新时间起播，并立即用新位置刷新空间参数。
- 手动拖拽对象会设置“锚点”，期间暂停轨迹驱动；点“恢复轨迹”或下次 seek/切段落即解除。

## 资源不足时的优先级与降级（不静默丢关键声音）

空间声道预算可在 1 / 2 / 3 之间切换。分配规则：

1. 按对象优先级降序（钟声 P3 关键叙事 > 鸟鸣 P2 > 脚步 P1），同优先级按 id 确定性排序。
2. 预算内的对象获得完整空间化；超出预算的对象**不静音**，而是 `fold=1` 折叠为中心等功率
   双单声道，并在反馈区产生 `VOICE_FOLDED` 显式上报。
3. Worklet 完全不可用时，整个内核降级为 `GainSpatialVoice`（双 GainNode + ChannelMerger），
   数学与 worklet 一致，仅平滑在主线程、非采样级，并产生 `WORKLET_UNAVAILABLE` 上报。

声源数量多本身不等于空间更真实：真实感来自明确的声像、距离、范围与时间建模，本项目不把
“加更多源”当作空间保真度。

## 叙事段落与事件时序检查

- 段落 A《林间破晓》、段落 B《回声回廊》，各 24 s，共 48 s；三段路径分别是环形、闭合折线
  巡逻、折返（B 段改为反向内圈 / 外缘包抄 / 对角折返）。
- 每个对象在段内有带时间戳的事件，到达时刻触发 accent 增益并写入“事件触发记录”，结果区的
  事件时序表对应行会高亮，可核对方向、能量与事件时序。

## 导出实际渲染声音

“导出当前段落 / 完整场景 WAV”使用 `OfflineAudioContext` 跑**同一条信号链**（含 worklet
空间化、范围、距离、事件增益与限制器），不是录制扬声器输出。导出完成后在结果区给出下载
链接、采样率、声道数与离线渲染耗时。

## 测试

- 纯逻辑：`node tests/logic.test.mjs`（等功率能量守恒、左右声像、范围 crossfeed、折叠、
  路径连续与场域约束、事件时序、WAV 头）。
- 端到端（需 Chromium/Playwright）：覆盖启动、播放轨迹、暂停/seek/跨段、预算降级上报、
  拖拽锚点、独听、WAV 导出，以及对导出音频的左右声道差异、声像摆幅与削波检查。
